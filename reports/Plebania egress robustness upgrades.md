# Fix live crash, harden egress pipeline

A two-line unpacking bug in `maintain()` crashes every pool refresh cycle, so the plebania egress never learns and four of seven faculties sit in DIRECT fallback while the dashboard still reports ROTATING. The crash is live and confirmed in code: `maintain()` unpacks two values from a `refresh()` that returns three, every 600-second cycle prints `too many values to unpack` and `last_error` stays null with no alert firing. Beneath that headline sit a half-dozen correctness defects in chaining transport, proxy DNS handling and fallback accounting that waste the 600-entry pool and leak operator IP on single-try-then-direct. The crawler compounds the problem by retrying too narrowly, learning rate-limit bursts as multi-hour Incapsula walls, and exiting clean while whole faculties silently skip. Source currency is actually sound — only WIM verifies live from datacenter egress while six hosts wall identically — so no URL or driver migration is indicated, only a home-egress recheck protocol. The cheapest hardening path reuses what is already on the box: Blackbox plus Prometheus probes, a CI gate that builds the egress image and runs the missing regression test, and disk triage on a `/srv` filesystem at 98%.

## Maintain() unpacking crash freezes pool learning every cycle

The single most urgent defect is a signature mismatch that disables all continuous verification. `maintain()` in `tools/egress/server.py:461-470` runs `ok, tried = pool.refresh()` inside a 600-second loop, while `refresh()` in `tools/egress/pool.py:319-380` returns a three-tuple `(alive_n, len(fresh), verified)`. Every cycle therefore raises, prints `pool refresh failed: too many values to unpack (expected 2)`, sleeps, and repeats, which matches the live `docker logs` tail exactly and leaves `/api/status.last_error` at null because the exception never propagates into pool state. The fix is a one-line unpack plus a regression test that imports and calls `maintain()` once, a path no existing test covers since `tests/test_egress.py:92-103` pins only the three-tuple return and routing round-trips. Effort is trivial, impact is total, and every recommendation below depends on refresh actually running.

Chaining transport carries four more correctness defects in `chain_connect()` at `tools/egress/server.py:112-154`, all verified by direct read. The SOCKS4a reply check demands an exact eight-byte `00 5A 00 00 00 00 00 00` match, while compliant servers may return any bind address on success and the reference implementation checks only the first two bytes, so working proxies are discarded as refused; relaxing to a two-byte status check recovers them at negligible cost. The `https://` upstream scheme falls through to cleartext CONNECT with no TLS wrap to the proxy, while probing via curl_cffi handles the scheme correctly, so entries from the `roosterkid-https` list probe alive yet can never chain; the choice is either TLS-wrap-before-CONNECT to match DeadDropMGMT parity or drop and reject `https` in `parse_proxy_url`, a small change that stops wasting pool slots on unchainable entries. Handshake readers lack absolute deadlines and size caps since `_recv_exact()` applies only a per-`recv` 10-second timeout and the CONNECT head loop accumulates unbounded until `\r\n\r\n`, where the hardened pattern caps heads at 32 KiB with an overall deadline ([read pattern](https://github.com/prometheus/blackbox_exporter/blob/master/CONFIGURATION.md)); adding the cap plus a robust status-code regex is a small change. Overlong hostnames raise `ValueError` from `bytes([len(hb)])` for lengths above 255, but `_open()` and `do_CONNECT` catch only `OSError`, so one bad hostname kills a handler thread with no client response; widening to `Exception` or validating length upfront is trivial. The `socks5://` probe path leaks DNS intent because `fetch_via()` passes the scheme verbatim to curl_cffi, where plain `socks5://` resolves the faculty hostname locally and only `socks5h://` delegates resolution to the proxy ([proxy semantics](https://github.com/curl/curl/blob/master/docs/libcurl/opts/CURLOPT_PROXY.md), [hostname option](https://curl.se/cvssource/docs/cmdline-opts/socks5-hostname.md), [leak comparison](https://highproxies.com/socks5-vs-socks5h/), [setup practice](https://www.proxies.sx/use-cases/developers/curl)); live tunnels are unaffected since `chain_connect()` already sends DOMAIN, but Round-2 faculty probes need a `proxy_curl_url()` rewrite plus accepting `socks5h` and `socks4a` in `SUPPORTED_SCHEMES`, a small change with a unit test pinning the rewrite. Fallback accounting is racy and misleading: `fallbacks` increments a plain dict without a lock while the GUI copies it from another thread, and the top banner shows ROTATING when any proxy is globally `ok` even though live status showed **4 of 7 hosts DIRECT with 577 of 600 entries failed**; making counters atomic and deriving top mode per-host truthfully is small.

| Change | Why | Size |
|---|---|---|
| Fix `maintain()` unpack to three values and add regression test calling it | Restores all pool learning; nothing else matters while refresh crashes | XS, under an hour |
| Relax SOCKS4a reply to two-byte status check | Recovers compliant proxies currently discarded | XS |
| Resolve `https://` proxy mismatch by TLS-wrap or list removal | Stops probing entries that can never chain | S, half a day |
| Add absolute handshake deadlines, 32 KiB head cap, status regex, widen except | Prevents hung threads and unanswered clients on hostile handshakes | S |
| Add `socks5h`/`socks4a` rewrite for probes and accept `h` schemes | Closes local-DNS leak on faculty Round-2 probes | S |
| Atomic fallback counters, truthful per-host top mode, fallback cause label | Stops misleading ROTATING banner and enables alerting on cause | S |

## Single-try proxy choice with frozen latency wastes the pool

Pool selection matches the reference design at a high level — tiering `ok` before `new` before `fail` with a latency tie-break — but omits every penalty that makes the reference stable under burst. `pick()` in `tools/egress/pool.py:189-210` never reads the `fails` counter that `mark()` increments, freezes the first global latency forever instead of decaying it, drops the rated-versus-unrated preference entirely, and returns a single candidate that `_open()` in `tools/egress/server.py:249-274` tries exactly once before falling back to direct, with no pool-wide circuit breaker, no overall CONNECT budget and no walk of alternatives. The hardened equivalent trips the whole pool for 60 seconds on wholesale failure, budgets 10 seconds per request with 2-second attempts, and walks fastest-first candidates; Python's threading server itself spawns an unbounded thread per request with no built-in cap ([socketserver behavior](https://docs.python.org/3/library/socketserver.html), [threading server](https://docs.python.org/3/library/http.server.html)), and each tunnel here costs **three threads held up to a fixed 120 seconds**, so concurrent crawl jobs against a dead pool can exhaust the **128-process and 256 MiB** container quickly. The practical upgrade is consecutive-failure backoff per proxy and per host, EWMA latency with periodic re-measurement, rated preference for SOCKS and anonymity-vetted lists, top-N `pick()` with a short-timeout walk before fallback, and a fingerprint-keyed 60-second trip that fails fast instead of holding a connect timeout per burst.

Probing has the right two-round shape — neutral OSM tile for aliveness then each chain host's own index with a content marker — but loose tuning and batch-only execution. Defaults of `max_probe=150`, 8-second timeout, 20 workers and `round2_cap=40` across up to seven thin hosts can schedule **up to 280 Round-2 probes per refresh**, and list fetching is sequential at 30 seconds per list with no per-source diversity cap and no latency cutoff in Round 1, so any 200 over 1000 bytes passes regardless of speed. There is no stale re-probe, no latency re-measurement and no failure-triggered fast re-probe of the entry that just failed on live traffic, only `mark()` plus thin-coverage detection plus 24-hour pruning. The fix keeps the split, adds a faculty-measured latency cutoff to Round 1, parallelises list fetches with per-list timeout and size cap, caps per-source contribution for diversity, scales Round-2 caps by per-host deficit instead of flat 40, enforces a global refresh deadline inside the 600-second interval, and adds continuous verification of oldest-unchecked entries plus a heal-kick on live failure. Threading and persistence need the same treatment: a bounded tunnel semaphore around 32 to 64 with 502/429 beyond it, an explicit queue size instead of the default of 5, a non-blocking refresh lock returning 202-already-running on `/api/refresh`, short critical sections with network and disk I/O outside the global lock, `fsync` plus backup rotation and entry caps on `pool.json`, monotonic clocks for cooldowns, explicit IP filtering that rejects reserved, multicast, link-local and unspecified rather than only private plus loopback, digest-pinned base image with a healthcheck, and `NO_PROXY` extended to the inner `172.30.77.0/24` network.

| Change | Why | Size |
|---|---|---|
| Failure-penalty backoff, EWMA latency, rated preference, top-3 walk, pool circuit breaker | Stops re-probing dead pools and leaking direct on first flaky best pick | M, two to three days |
| Round-1 latency cutoff, parallel list fetch, per-source caps, deficit-scaled Round-2, refresh deadline, stale re-probe plus heal-kick | Cuts refresh stalls and keeps coverage warm between reseeds | M |
| Tunnel semaphore, queue tuning, refresh lock, low-priority probe executor | Prevents thread and memory exhaustion under concurrent crawls | S to M |
| Split locks, debounced saver, `fsync` rotation, monotonic cooldowns, strict IP filter, digest pin, healthcheck, wider `NO_PROXY` | Removes corruption, clock-skew and container drift classes | S each, M as a batch |

## Crawler confuses rate limits with walls and misses redesigns silently

Retry classification is too narrow and its exhaustions are mistaught as blocks. `get_with_retry` in `tools/refresh/refresh.py:59-67` retries only exceptions plus 429/500/502/503/504, returns every other status as an instant verdict, backs off roughly 15 seconds worst-case per page with only plus-zero-to-one jitter, and on exhaustion raises something the caller records as `blocked_at` while feeding `BlockModel` a bogus multi-hour cooldown that was never labelled by cause. Statuses 408 and 425, redirects and partial bodies score as walls, and empty-200 bodies with `page_ok` false count as skipped while the run stays complete, so truncated pages look clean. Block learning then doubles the error because WLO and WEL share one Incapsula policy yet learn, estimate and probe per faculty, the **default 2-hour estimate exceeds the 90-minute wait budget** so the fifth quadratic probe at 120 minutes is unreachable, give-ups learn nothing, and any probe exception scores as still-blocked. Orchestration starves later faculties on one shared sequential budget, ahead-pass blocks trigger wasteful full main-pass reruns that overwrite `fac['run']`, and time-budget cuts, discover errors, empty indexes and robots refusals all return indistinguishable not-complete with no issue while mass-404 and mass-skip return complete with no alarm and state saves only every 25 changed writes. Pacing is politely sequential on fixed 4-to-9 and 2.5-to-6 second profiles with no adaptation to 429s or latency, while WTC mutates the shared session `Referer` globally and one cookie jar spans unrelated hosts and survives blocks with possibly poisoned cookies. State resets silently to empty on corruption with no backup or metric, wall-clock `fresh()` with a 20-hour default trusts runner time absolutely, current-semester keys are term-less so winter checks count fresh in summer, and the raw-hash plus `same_plan` double check pays full conversion before discarding cosmetic diffs. Every driver parses with brittle regexes — `<gro href>`, iframe `src`, Drupal menu options, hidden-data-island divs — and fails silent-clean, while converter contracts differ per driver and WCY ignores a return-code failure that falls through to a missing `out.ics`. Scheduling at 01:23 daily with a 200-minute cap under a 240-minute timeout is coherent steady-state but over-crawls stable mid-semester weeks and under-reacts during August and January-February publication windows.

| Change | Why | Size |
|---|---|---|
| Three-way transient versus block versus verdict taxonomy, empty-body guard, capped proportional jitter, per-faculty retry budget with exported counts | Stops learning flaky transport as Incapsula walls and surfaces flakiness | M, two days |
| Per-policy-group `BlockModel`, group probe schedule, budget-matched probe count, EWMA estimator, cause-labelled episodes | Halves WLO and WEL probe traffic and fixes unreachable-probe budgets | M |
| Per-faculty wait caps with round-robin probes, ahead-only reruns, machine-readable `incomplete_why`, degraded signal with mass-failure alarms, check-driven saves | Converts silent redesigns and starvation into issues instead of clean exits | M, two to three days |
| AIMD pacing per policy group persisted in state, scoped WTC `Referer`, per-group cookie jars with post-block reset, robots cache | Lowers WAF score without burning self-hosted trust | S to M |
| Corrupt-state backup plus alarm, future-timestamp-tolerant `fresh()`, term-scoped keys, per-driver 304-rate logging, normalized-hash fast path | Prevents thundering recrawls and wasted full-body downloads | S each |
| Quote-tolerant index regexes plus XML parser fallback, per-driver canaries on listed and convert rates, normalized converter contracts, page-shape fixtures, toolchain version gating | Turns first-break parsing into an alarm instead of a silent skip | M |
| Window-aware cadence with per-faculty `fresh_hours` and index-only change detector | Spends request budget where plans actually change | M, staged after metrics |

## Six faculties stay walled from datacenter while observability gaps hide failures

Live verification from datacenter egress on 2026-10-14 is unambiguous: only the WIM index at [WIM index](https://www.wim.wat.edu.pl/wp-content/uploads/rozklady/zima/index.xml) returns 200 with a current `WIM - zima 2026-27` period tag matching `season_of`, while WLO, IOE and WCY answer 302 `Loading` and WEL, WTC and WML answer 403 Incapsula incident pages, all from the same wall rather than from dead URLs. Configured bases in `sources.json` for WLO, WEL, WIM, IOE, WCY, WML and WTC therefore stand, IOE stays pinned to `lato/` until the self-hosted runner sees a live 200 with a current period on both `lato/` and `zima/` candidates at [IOE index](https://ioe.wat.edu.pl/plany/lato/index.xml), season rollover and the August plus January-February two-term logic need no change, and only WIM `robots.txt` at [WIM robots](https://www.wim.wat.edu.pl/robots.txt) is readable from here with a permissive allow while the other six are wall artefacts rather than prohibitions. No driver migration is indicated since WIM still matches `plansoft` expectations at index level and blocked hosts could not be re-verified, WIG is correctly out of scope behind authenticated E-DZIEKANAT per [WIG schedules](https://wig.wat.edu.pl/cpp/index.php/studenci/plany-rozklady-terminy/rozklady-zajec) within the eight-unit teaching map at [WAT study](http://www.wat.edu.pl/ksztalcenie/) and [unit portals](https://irk.wat.edu.pl/pl/offer/S2_LATO_25_26/units/), and the only actionable source-currency work is documentation plus a runner-side recheck protocol. That protocol is one `index.xml` or landing fetch per blocked host from the home address confirming reachability, group counts, generation dates and period tags, one group-page sample only when an index looks different, explicit checks that WML still yields exactly one `index.xml` iframe, WCY still carries `lessons hidden` with the date gate, WTC entries are still PDFs and the IOE grid is still the transposed variant, and recording WIG as intentionally uncovered rather than adding a driver. Effort is under a day of runner-side fetching plus config-note updates.

Operations hardening starts from the same live evidence and the cheapest notifier is already installed. Only crawl blocks open a GitHub issue while empty pool for hours, egress down, runner offline, disk filling and GUI unreachable have no alert, yet the box already runs Prometheus, Blackbox, Grafana and cAdvisor side by side, where the canonical down signal is `probe_success == 0` with duration and certificate metrics ([exporter rules](https://docs.ping7.io/docs/exporters/blackbox/rules.html), [probe example](https://docs.appuio.cloud/user/how-to/monitor-http-endpoints.html)). The GUI misleads by design when most faculties are DIRECT, exposes per-host rows without percentiles or threshold progress, shows only last-ten runs with no in-progress or next-scheduled state, binds LAN-wide with unauthenticated `POST /api/refresh` and `/api/run` that let any LAN caller trigger 150-candidate refresh loops or inject persisted run rows, and refreshes whole-page every 30 seconds with no event cue. Logging keeps one unstructured line per tunnel with no request or job ID, swallows transport detail to bare `None`, and retains only coarse fallback and block counters, while deployment ships by manual `scp` with hand-merged compose, unpinned base image, no egress build or scan in CI and no healthcheck, so signature changes ship straight to the box. Single-box reliability is the near-term killer with root at **84% and `/srv` at 98%** backing all volumes, no backup for learned pool or runner credentials, and limits that fit current use only while neighbors dominate RAM. The practical sequence adds Blackbox probes on `/api/status` with critical on five minutes down plus pool-derived, disk and `up` rules routed through existing Grafana contacts, a container healthcheck paired with an autoheal-style restarter since health alone never restarts ([health versus restart](https://yurtbay.dev/blog/docker-healthcheck-restart-policy/en/), [restart policies](https://techearl.com/docker-restart-policies-health-checks), [unhealthy discussion](https://forums.docker.com/t/unhealthy-container-does-not-restart/105822)), token auth on mutating GUI routes, JSON-structured one-line tunnel logs with job ID and verdict, a CI job building the egress image with pinned digest plus the `maintain()` regression test plus compose validation plus image scan, and immediate disk triage with volume backup before any other ops work, referencing [compose semantics](https://docs.docker.com/reference/compose-file/services/) and [tmpfs mounts](https://docs.docker.com/engine/storage/tmpfs/) for the hardening details.

## Conclusion

The highest-leverage insight is that robustness work is blocked behind correctness: restoring a crashing refresh loop and closing a DNS leak plus a fallback race buys more resilience than any new pool heuristic, and the crawler's biggest win is taxonomic rather than volumetric since distinguishing transient noise from real walls halves wasted probes without spending an extra request. Treating source currency as a verification protocol instead of a migration project keeps the system current with wat.edu.pl at minimal risk, while routing all infra alerting through the already-running Prometheus stack avoids a new monitoring silo during the exact periods when Actions-based alerting cannot run.
